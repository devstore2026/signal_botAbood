# Abood Trading — إصلاح استضافة Render

## نطاق هذا التعديل
التعديل خاص بالاستضافة وإدارة التشغيل فقط؛ لم يتغير محرك الإشارات أو الصور أو قرارات التداول. هذه الحزمة لا تقدّم دليلاً على الدقة أو الربحية. نسبة Accuracy التي تعرضها النسخة الأصلية هي تحويل لعدد توافقات المؤشرات، وليست احتمال نجاح معايراً أو نسبة فوز مقاسة.

## ما وُجد في النسخة المرفقة
خادم HTTP و/health كانا موجودين بالفعل. لذلك رسالة Received SIGTERM وحدها لا تثبت أن سبب التوقف هو غياب المنفذ. يلزم الرجوع إلى Events وDeploy logs في Render في نفس وقت الإيقاف لتحديد هل هو فشل health check أم redeploy أم سكون الخطة المجانية أو إجراء من المنصة.

## الإصلاحات
- start_web_server يبدأ أولاً داخل main ويستمع إلى 0.0.0.0 على PORT، أو 10000 محلياً عند غيابه.
- GET / وGET /health يعيدان 200 بالنص: Abood Trading Bot is running!
- يحتفظ main بمرجع AppRunner ويغلقه بصورة سليمة عند الإنهاء أو أخطاء بدء التشغيل.
- البوت وFeed وخادم HTTP يعملون على حلقة asyncio واحدة؛ لا يُستخدم web.run_app الذي سيحجز الحلقة.
- حلقة Feed تعمل دائماً، تعيد الاتصال بعد 3 ثوانٍ عند الخطأ أو إغلاق الاتصال، ولا توقف polling بسبب ConnectionError. يحتفظ Feed بطلبات الاشتراك لإعادتها عند الاتصال التالي.
- CancelledError لا يُبتلع؛ SIGTERM إشارة إنهاء عادية يجب احترامها، لا مقاومتها بإعادة تشغيل داخل العملية.
- تُراقب مهام الخلفية حتى لا يبقى HTTP ظاهرياً سليماً بينما العامل الأساسي انهار بشكل غير متوقع.
- إفراغ سجل النتائج عند الإنهاء محدود بثلاث ثوانٍ، ثم إغلاق جلسة تيليجرام وخادم HTTP.
- متغيرات Render لها الأولوية على .env المحلي: load_dotenv(..., override=False).
- لا يُرفق .env ولا توكنات. يوجد .env.example و.gitignore.

## الرفع على Render
1. ارفع محتويات مجلد abood_signal_bot إلى جذر المستودع؛ يجب أن يكون bot.py وrequirements.txt وrender.yaml في نفس المستوى، لا داخل ex/ex.
2. للخدمة القائمة اضبط Root Directory على مجلد المشروع الصحيح إن كان داخل مجلد فرعي.
3. Service Type: Web Service، Runtime: Python.
4. Build Command: pip install -r requirements.txt
5. Start Command: python -u bot.py
6. Health Check Path: /health
7. Environment: BOT_TOKEN وPO_AUTH_FRAME وPO_WS_URL. ضع القيم السرية من لوحة Render محلياً، ولا ترسلها في المحادثة أو GitHub.
8. PORT يوفره Render تلقائياً؛ لا تُثبّت منفذاً آخر في الكود.
9. انشر التحديث، وتأكد من ظهور:
```
[Web] Health-check server listening on 0.0.0.0:10000
[Bot] Running polling; HTTP health server is already listening
```
قد يختلف رقم المنفذ بحسب PORT. افتح https://YOUR-SERVICE.onrender.com/health ويجب أن ترى:
```
Abood Trading Bot is running!
```
10. شغّل نسخة polling واحدة فقط لنفس التوكن. لا تُشغّل نسخة محلية بالتزامن أثناء الاختبار على Render.

لخدمة جديدة يمكن استعمال Blueprint وملف render.yaml بدلاً من الإعداد اليدوي.

## حدود الخطة المجانية — مهم
بحسب وثائق Render، خدمة Web Service المجانية تسكن بعد 15 دقيقة دون حركة واردة. Telegram polling واتصال Feed ينشئهما التطبيق إلى الخارج، ولا تعتمد عليهما كطلبات واردة لإبقاء الخدمة مستيقظة. فحص health يثبت أن المنفذ يستجيب؛ ليس ضمان uptime ولا وسيلة لإلغاء قيود المنصة. قد يعيد Render تشغيل الخدمة أيضاً، ويرسل SIGTERM أثناء النشر أو الإيقاف.

لن يتجاهل هذا الكود SIGTERM، ولن يستطيع إبقاء polling أو Feed يعملان بعد إيقاف الحاوية من المنصة. للتشغيل المستمر اختر استضافة تدعم عاملاً دائماً أو خدمة مدفوعة مناسبة. لم تُضف هذه الحزمة خدمات ping خارجية أو وعود تشغيل 24/7.

الملفات المحلية على Render Free مؤقتة: سجل paper_results وبيانات الذاكرة قد تضيع عند إعادة التشغيل أو النشر أو السكون؛ الحزمة لا تضيف قاعدة بيانات خارجية.

## التشخيص
- /health = 200: عملية HTTP تستجيب فقط؛ ليس إثباتاً لاتصال الأسعار أو المصادقة.
- /status داخل تيليجرام: يفحص حالة Feed الفعلية.
- Feed disconnected: سيحاول الاتصال بعد 3 ثوانٍ. إذا تكرر، راجع الشبكة وصلاحية جلسة الحساب التجريبي وصيغة الأحداث؛ إعادة المحاولة لا تصلح جلسة منتهية.
- Received SIGTERM: راجع Events حول نفس وقت السجل. لا توجد بيانات كافية في هذه الرسالة وحدها لتحديد السبب.
- No open ports detected: راجع مسار المشروع وStart Command وظهور سجل [Web]؛ تأكد من أن Render نشر هذه النسخة لا نسخة أقدم.
- Missing BOT_TOKEN: أدخله في Environment؛ فشل الإعدادات المقصود لا يُخفى بإبقاء خدمة وهمية تعمل.

## التشغيل المحلي
انسخ .env.example إلى .env وضع إعداداتك محلياً، ثم:
```
pip install -r requirements.txt
python bot.py
```

## اختبارات الإصلاح
```
python -m unittest discover -s tests -v
```
11 اختباراً خاصاً بالاستضافة: طلبات HTTP حقيقية إلى منفذ محلي مؤقت، / و/health، استقلال liveness عن Feed، PORT غير صالح أو محجوز، أولوية البيئة، إعادة الاتصال كل 3 ثوانٍ، وإغلاق الموارد. اتصالات المنصة وتيليجرام محاكاة للاختبار؛ لم ننشر على حساب Render الخاص بك.

الاختبارات القديمة في legacy_tests تعكس متطلبات نسخ أقدم وقد لا تتوافق مع منطق الإشارات الحالي؛ لا تُقدّم بوصفها اختبارات اجتازتها هذه الحزمة.

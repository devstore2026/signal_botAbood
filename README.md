# Abood Trading — محرك S5 تجريبي زمني

## ما الذي أُنجز
عدّل محرك صفقات 5 ثوانٍ فقط. الاستضافة والبانرات والأزرار والاتصال بالمنصة باقية، ومدد 15 ثانية فما فوق تستعمل `strategy_legacy.py` الأصلي دون تعديل. هذه نسخة بحثية، ليست تحقيقاً مثبتاً لنسبة نجاح 80–90%.

## تصحيح مهم لقراءة الدقة
في النسخة الأصلية: `min(80, 55 + votes*3 + bonus)` هي مصدر Accuracy rate. مثال: 4 توافقات = 67%. هذا رقم واجهة وليس إحصاء نجاح. عرض النسبة لا يثبت أو ينفي أن المستخدم حقق 67% فعلياً.

الآن تعرض البطاقة:
- Confluence: عدد التوافقات، ليس احتمال الفوز.
- Accuracy rate: نتيجة PAPER المقاسة للأصل والمدة والإعدادات الحالية، أو Not established حتى تكتمل MIN_STATS_SAMPLE.
- يحسب القياس الورقي التعادل ضمن المقام، ويفصل المشاهدات غير الصالحة. التنفيذ الحقيقي وأرباحه غير مقاسين.

## تغييرات S5
1. استخدام الأزمنة الفعلية في تقدير الانحدار والـEMA؛ سرعة التكات متغيرة، فلا يكفي عدّ التكات.
2. تجميع آخر تكة داخل كل ربع ثانية لتخفيف هيمنة دفعات الرسائل المتقاربة.
3. مقارنة انحدار السعر عبر نوافذ ثانيتين و5 و12 ثانية، ومتوسطين أُسيين بزمن استجابة 0.8 و2.2 ثانية.
4. قياس استمرارية صعود/هبوط التكات وكفاءة المسار والتسارع وRSI، مع تحذير من القفزات والمنحى المتشبع المتباطئ. عدّ التكات ليس دفتر أوامر أو حجم تداول.
5. استبعاد القيم التالفة والتكات المستقبلية والمنقطعة والقديمة؛ لا يولّد مسار S5 قرارات عشوائية عند غياب البيانات.
6. إزالة قلب الاتجاه القسري عند تكراره. تكرار الاتجاه ليس وحده عيباً.
7. فصل سجلات القياس بمعرّف profile جديد يتغير مع إعدادات المحرك؛ لا تخلط نتائج الاستراتيجية القديمة بالجديدة.

المؤشرات مترابطة؛ ثمانية توافقات لا تعني ثماني أدلة مستقلة ولا ثقة إحصائية 90%.

## التشغيل
Python 3.11+، كما في المشروع الحالي:

```sh
pip install -r requirements.txt
# ضع أسرارك محلياً في .env أو متغيرات Render، لا تنشرها.
python bot.py
```

متغيرات البيئة الحالية على Render تبقى كما هي. `.env.example` يحتوي الإضافات. غياب .env في الحزمة الأصلية مقصود: لم نضف توكناً أو جلسة جديدة ولم نتصل بحسابك. ملف render.yaml المرفق محفوظ دون تغيير. لا يوجد ضمان لاستضافة مجانية 24/7 أو نجاح self-ping.

## مستويان للتجربة
```env
S5_WINDOW_SECONDS=20
S5_MIN_SPAN=5
S5_MIN_TICKS=30
S5_MIN_QUALITY=65
S5_STRICT_FILTER=false
```

- الافتراضي false يحافظ على طلب إشارات مستمرة عندما تكون البيانات صالحة. البيانات الغائبة/القديمة محجوبة بصراحة في جميع الأوضاع، ولا تعوّض بمحاكاة.
- true يرفض أيضاً الإعدادات الضعيفة ويعرض سبب الرفض، فتقل الإشارات. ليس ضماناً لزيادة نجاحها؛ قارن أولاً.
- QUALITY حد توافق هندسي 0–100، لا نسبة نجاح. المعلمات ليست محسّنة على بيانات حسابك لعدم توفر تسجيل تكات في الأرشيف.
- ANALYSIS_MIN وANALYSIS_MAX يحددان وقفة الواجهة القائمة 1–3 ثوانٍ. التحليل يستخدم أحدث البيانات بعد الوقفة. زمن إيصال Telegram يظل موجوداً.

## التحقق خارج عينة التطوير
الأرشيف المرفق لا يحتوي سجل تكات تاريخي أو نتائج كافية لقياس نسبة نجاح جديدة. لا يوجد backtest حقيقي هنا؛ الاختبارات المرفقة بيانات اصطناعية لفحص المنطق فقط.

لتشغيل مقارنة على تسجيل حقيقي مستقل، جهّز CSV بهذه الأعمدة، دون أسرار:

```csv
symbol,timestamp,price
EURUSD_otc,1792400000.1,1.08321
EURUSD_otc,1792400000.4,1.08322
```

هذه الأسطر توضيح للصيغة فقط وليست أسعاراً حقيقية. timestamp بالثواني منذ Unix، متزايد لكل أصل؛ السجل المتكرر/غير المرتب يرفض صراحة.

```sh
python evaluate_s5.py ticks.csv --latency 0.3 --max-gap 1 > evaluation.json
```

يقارن على نفس مواعيد الطلب غير المتداخلة: الأصلية، والجديدة المستمرة، والجديدة المفلترة. الدخول من أول تكة بعد التأخير المفترض، والانتهاء من أول تكة بعد خمس ثوانٍ؛ الفجوات تُوسم invalid. يعرض عدد النجاحات والخسائر والتعادلات، ونسبة التغطية، وفاصل Wilson 95%. اختلاف نسب التغطية يعني أن المقارنة ليست صفقات متطابقة دائماً. المعلمات ثابتة ولا يجري تدريب أو ملاءمة على CSV. استخدم فترة زمنية لاحقة مستقلة، ولا تختَر أفضل أصل/فترة ثم تعلنها نتيجة عامة؛ الاختبارات المتكررة واختيار الفترات يسببان انحيازاً.

جرّب أكثر من قيمة تأخير واقعية، وعدة أيام وأصول. لا ترفع النسبة المكتوبة يدوياً، ولا تعتَمد عينات قليلة أو الربح بعد التدبيل كقياس لدقة كل إشارة. النتائج الورقية لا تمثل بالضرورة تعبئة الأوامر أو التسوية أو العائد الحقيقي.
